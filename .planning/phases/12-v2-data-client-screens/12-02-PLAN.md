Contract this plan CREATES (consumed by 12-04 fetcher.py and 12-05 main.py — implement exactly these names):

fetch_schedule.py
- Job name constants (str): OVERVIEW = "overview", STORAGE = "storage", HISTORY = "history", TEMPERATURE = "temperature", DEVICES = "devices"
- class FetchPlan:
  - __init__(self, storage_interval=timedelta(minutes=55), retry_after=timedelta(minutes=60), max_attempts_per_slot=3, devices_retry_after=timedelta(hours=6), midday_hour=12, overview_backoff_after=3, overview_backoff_interval=timedelta(minutes=60))
  - due(self, now: datetime, has_battery: bool, battery_known: bool) -> Set[str]   (now is timezone-aware site-local time; returns an EMPTY set when in backoff and the backoff interval has not passed — the caller then skips the whole round, including the token pre-check)
  - in_backoff (read-only property, bool): True after overview_backoff_after consecutive failed OVERVIEW records, False again after the next successful OVERVIEW record. Callers pass retry=not plan.in_backoff to api.get_overview (12-04)
  - record(self, job: str, now: datetime, success: bool) -> None
  - HISTORY_CALLS = 2 (class attribute: calls per history fetch, D-10), used by the budget test and by fetcher logging

battery_cache.py
- load_battery_cache(path: Union[str, Path], site_id: str) -> Optional[bool]
- save_battery_cache(path: Union[str, Path], site_id: str, has_battery: bool) -> bool   (True if written)

Analog for atomic write: token_store.TokenStore.save (mkstemp in target dir, os.write loop, os.fsync, os.close, os.replace, unlink tmp on any exception). Analog for tolerant load: token_store.TokenStore.load.

One record(OVERVIEW, success=True) resets the counter and in_backoff to False, and the next due() is back to every-poll overview
    - Backoff does not trigger after 2 failures, or after failures interleaved with a success (fail, fail, success, fail → not in backoff)
    - Storage: due only when has_battery is True and (never attempted or now − last attempt >= storage_interval); timing is by attempt, so a failing storage call is retried no faster than hourly
    - History: due when no success yet for now.date(); after a failure, due again only when now − last failure >= retry_after; at most max_attempts_per_slot attempts per local date
    - Temperature: only when has_battery; two slots per local date: "am" (hour < midday_hour) and "pm" (hour >= midday_hour); due when the current slot has no success, with the same retry_after gap and attempt cap per slot. A service start at 14:00 only fetches the pm slot
    - Devices: due only when battery_known is False; after a failure, due again only after devices_retry_after
    - Day rollover: a new local date resets history and temperature slots (history fetched again on the first poll of the next day)

    - Without battery: storage and temperature never due
